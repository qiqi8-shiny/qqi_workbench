四、方法部分
  • 文本：文本源扩展至权利要求书，jieba 分词 + 停用词 + 词性筛选，LDA(K=15)（困惑度 + 一致性 c_v 双指标网格搜索，K=5–31、seed=42），不是瞎设 K。
  • 结构化：技术/主体/经济/法律多维特征工程 + LDA 主题 + K-Means(K=5) 聚类特征。
  • 防泄露（最硬的方法严谨点）：主动识别并移除"专利维持年限"等含未来信息的特征，并采用时间分割——杜绝用未来信息预测过去。
  • 模型：LR / SVM / RF / XGBoost 等多模型横向对比，GridSearchCV 调优，按 F1-macro 评估（因为类别不平衡，不用准确率糊弄）。
  • 可解释（SHAP）：从测试集抽取 1500 条代表性样本（seed=42）开展 SHAP 分析——树模型用 TreeExplainer、线性模型用 KernelExplainer，量化每个特征对预测的贡献，回溯驱动高转化的关键因素，把黑盒模型变成能解释的白盒。

随机森林最优，F1-macro 0.6606、F1-weighted 0.8780（数字来自实际模型对比，可放心讲）。
建立"医用成像器械专利可转化预测框架"：LDA 揭示技术主题分布 + SHAP 回溯驱动高转化的关键因素 → 转化为可解释的专利布局建议。

七、技术深挖 Q&A 防御库
Q：LDA 和 BERT 类模型比，是不是太老？
A：课题目标是可解释的主题分布，LDA 的主题词人是能直接读的，比嵌入向量更适合给业务方讲；而且我们用困惑度+一致性双指标调优，不是拍 K。如果追求语义深度可以上 BioBERT，但可解释性会牺牲。
Q：F1-macro 0.66 不算高吧？
A：这是类别不平衡下的 macro 均值，且数据本身噪声大（专利文本）。我的贡献重点在数据质控和可解释，不是刷分；0.66 在同类专利转化预测里是合理水平。
Q：为什么用 F1-macro 不用 AUC？
A：多类别下 macro-F1 对少数类更敏感，能暴露不平衡问题；AUC 在类别不平衡时容易虚高。两者都看，汇报用 F1-macro 更诚实。
Q：你说的"防泄露"具体指什么？
A：最典型是"专利维持年限"——一条专利如果已经维持了很多年，本身就意味着它活下来了、转化概率高，但这个信息是申请之后才有的未来信号，拿来当特征就是作弊。我把它和这类字段全移除，并用时间分割训练/测试，保证测试集时间上严格晚于训练集。
Q：SHAP 是什么？你为什么一定要做模型可解释？
A：传统机器学习/深度学习模型常是"黑盒"——只输出预测结果，说不清"为什么判它高转化"。SHAP 基于博弈论的特征归因，能对每一个样本量化"每个特征把预测往正类推了多少"，把黑盒变成白盒。我坚持做可解释，一是因为我的核心价值不是给个分数，而是给业务方能直接用的"为什么"；二是可解释能反过来验证特征工程有没有泄露、有没有荒谬驱动——它是我这套框架里和"防泄露"并列的另一块严谨招牌。
Q：全部样本做 SHAP 算力很大吧？你怎么做？
A：对，全量 SHAP 在树模型上要算每个样本每个特征的边际贡献，算力开销很大。所以我从测试集随机抽取 1500 条代表性样本（固定随机种子 seed=42，保证可复现）开展 SHAP 分析；树模型（随机森林）用 TreeExplainer、线性模型用 KernelExplainer。1500 条足以稳定估计特征重要性排序，且结论可复现——这也是我对算力/质量权衡的一个务实处理。
Q：你的 SHAP 得出了什么结论？哪些因素真正驱动高转化？
A：SHAP 平均重要性显示，驱动预测的因素是"法律强度 + 核心成像 IPC + LDA 文本主题"三类互补，不是单一来源：
  • 法律强度类最突出：简单同族专利申请数量（同族规模，反映布局广度与稳定性）贡献最高，权利要求近似数量（权项数，反映技术保护厚度）次之；申请人类型里"高校"明显靠前——说明高校/科研主体的专利更易被许可、转让。
  • 核心成像 IPC：G06T（图像数据处理，医用成像核心赛道）、A61B（诊断/外科器械）贡献显著，正好印证课题聚焦"医用成像器械"这个细分赛道。
  • 文本语义类：多个 LDA 技术主题（主题_3/4/2/8/1 等）进入 Top 特征，说明权利要求书的文本本身携带可转化信号，不是只靠结构字段硬凑。
这三点可直接转成专利布局建议——扩同族、补权项、盯核心 IPC、优先看高校来源——这就是可解释带来的业务落地价值，也是我比起同方向黑盒研究多出来的一块。
Q：为什么先用大为智慧芽小样本、再换知网？
A：先小样本把方法验证扎实，调参快、成本低；验证稳了再迁移到知网大数据（66,082 条，约为智慧芽 2 倍），避免在大库上反复试错。迁移时我还重新对齐了字段 schema（知网 28 列 vs 小库 21 列），按法律唯一号去重，保证方法在大数据上仍可靠。
Q：知网 66,082、你建模才 42,849，中间怎么筛的？
A：66,082 是知网按检索式（6 个 IPC + 中英关键词）原始导出的医用成像器械领域总量；先 Python 脚本二次查准（保留/排除词表）保留 43,463 条，再去重（按公开号）得 42,849 条建模样本。每步可解释、可复核，不是随便砍。
Q：多分类还是二分类？标签到底怎么定的？
A：我把"标签怎么定"当成独立子任务，在约 4.3 万条样本上对二分类和 7 种三分类方案（按"转移3/许可2/质押1"加权、转移中心、事件计数、不同阈值等）做了系统对比。结论很明确——三分类无论怎么分都高度不均衡，数据里其实只有两种结构：要么"中类坍缩"（M1/M1b/M3 里"只许可或只质押"的中类仅占 2.8%），要么"高类压到极稀疏"（M4/M5/M2b 里高类 ≤0.7%，M2 高类甚至只有 9 件，而 SHAP 每类至少需数百样本才稳，解释力根本不可靠）。最理想的 M1 方案（转移3/许可2/质押1，≥3 为高 / 1~2 为中 / 0 为低）高类 16%，基本就等于二分类正类 18.8% 减去那 2.8% 的"仅许可/质押"——三分类相对二分类几乎没有增益。所以我最终定的是二分类作主结果，同时用 M1 三分类做敏感性 / 鲁棒性分析（同一套特征重跑一次三分类标签，单独一小节报告"换标签后结论是否稳健、中类稀疏如何限制三分类"）。这样既拿到最稳的主结论，又诚实地把方法边界交代清楚——比硬做三分类虚报精度更经得起答辩追问。
Q：做标签划分的时候有没有遇到什么问题？
A：有，最棘手的是"多分类划不准"。三分类无论怎么加权都高度不均衡——数据里其实只有两种结构：要么中类坍缩（"只许可或只质押"的中类仅 2.8%），要么高类压到极稀疏（M4/M5/M2b 高类 ≤0.7%，M2 高类甚至只有 9 件，而 SHAP 每类至少需数百样本才稳，解释力根本不可靠）。所以我没有硬上三分类，而是退回二分类这个最稳的口径。
Q：如何保证你的标签划分结果是稳健可靠的？
A：两道防线。一是"查准背书"——标签来自转让/许可/质押三类真实法律事件，固定随机种子抽 400 件人工核对，查准率 ≈97%，不是拍脑袋打标；二是"敏感性 / 鲁棒性分析"——我保留了一套相对理想的三分类方案（转移3/许可2/质押1），用同一套特征重跑一次三分类标签，单独看"换标签粒度后结论是否还稳"，确认主结果不因标签定义方式而漂移。这比只报一个数更诚实。
Q：样本量够吗？
A：医用成像器械是细分领域，知网原始 66,082、二次查准 43,463、建模样本 42,849（约 4.3 万），是合理规模；且我有"先小样本验证再迁移"的流程控制和 97% 查准背书，质量重于数量。

四、标签构建最硬的方法严谨点，必讲
"召回标签最容易翻车：召回库填报滞后，如果直接用'是否已召回'当标签，会偷偷用未来信息预测过去（前视泄漏）。"
我的做法：以报告接收日为锚点，设计前向时间窗（0–2 年）匹配召回库——报告日后 2 年内发生的召回才算正样本，从根上杜绝泄漏。
型号级 / 厂名级双标签：型号缺失时以厂名级兜底，提升召回敏感性（宁漏勿错配）。

  • 文本：BioBERT / ClinicalBERT 提取 [CLS] 768 维句向量作语义特征。
  • 融合：与厂商/事件类型独热、年份、文本长度等结构化特征多模态拼接（768 维 + 结构化）。
  • 模型：LR / SVM / DT / RF / XGBoost / MLP 集成横向对比，GridSearchCV 调优，SMOTE + 代价敏感（class_weight='balanced'）处理不平衡。
  • 时序（设计）：Transformer / LSTM 时序支路（滑动窗口 SEQ_LEN=10）捕捉同型号故障时间演变。
  • 防泄漏：按器械型号分组交叉验证（GroupKFold）——同型号不跨训练/测试，防信息泄漏。
  • 可解释：SHAP 量化特征贡献。

七、技术深挖 Q&A 防御库
Q：为什么用 MAUDE 不用国内数据？
A：国内自发报告数据库不完整、字段缺失，MAUDE 是唯一大体量公开源；这是课题明确边界，论文里写了局限。
Q：产品码 JAK 不可靠，你咋保证筛对？
A：正因产品码不可靠，我才没只靠码——建了"器械名称 + 事件文本 + 型号 + 产品谱系"四重判据，文本只用于事后抽查举证，主体靠设备表三列名称判定；剔除池 95.7% 是呼吸介入导航类误报，说明判据有效。
Q：BioBERT 和通用 BERT 区别？
A：BioBERT 在生物医学语料上继续预训练，对医学术语（如 CT 机型、并发症名）语义捕捉更好；[CLS] 向量是整段文本的句级摘要，768 维直接进模型。
Q：前向窗为什么是 2 年不是 3 年？
A：召回填报滞后通常 1–2 年，2 年窗覆盖绝大多数真实召回又不泄露未来；过长会混入无关事件、过短会漏掉滞后召回。这是基于召回库填报周期定的。
Q：为什么你的召回匹配是按型号（model number），而不是批号（lot）或序列号（serial number）？
A：理想状态下，精准匹配当然应该用批号甚至序列号——召回本身就是"某一型号下的若干批号/序列号段"，粒度越细越准。但 MAUDE 的数据维护质量较差，很多报告的批号、序列号字段是缺失的：我实际查过字段填充率，model_number（型号）约 89%（最完整、可作分组键），lot_number（批号）只有约 16%，序列号基本不存。如果硬要做批号级匹配，会直接丢掉八成以上样本，建模根本跑不起来。

所以退而求其次，我用型号做匹配键，型号缺失时再用厂名级（manufacturer-level）兜底，尽量把召回样本抓全。代价是型号级匹配会比批号级粗，会带来一定假阳性——这个我会在论文里明确写成局限性，不讳言方法边界。这也正好呼应我方法里"按型号做 GroupKFold 分组交叉验证"：同型号不跨训练/测试，既防泄漏、又和召回的物理单元一致。
八、身份 / 进度防御
Q：模型跑完没？结果多少？
A：数据管道和标签体系已经建成落地，BioBERT 句向量（B 阶段）已跑完，建模对比是下一步。但数据质控流程（四重判据 + 前向窗标签）本身就是可复用的方法论贡献，不依赖模型出数——这点我能在白板上讲清楚。
九、弱点圆场
Q：样本才两千多，少不少？
A：CT 是细分器械，MAUDE 里 JAK 码就这些；我靠四重判据保证"少而干净"，且扩窗到 2005 后到 2582 份。质量 > 数量，而且对标文献（如 Santiago-Pérez 呼吸机 3992 条）我的规模是合理量级。
Q：类别不平衡 1:2.1 怎么处理？
A：SMOTE 过采样 + class_weight='balanced' 代价敏感双保险，评估看 F1 而不是准确率。

本页跳转： 文献计量是什么信息表怎么归纳全流程难点
文献计量板块 · 面试问答开场点题 · 背这条
Q：文献计量是什么？
A：文献计量学，简单来说，就是以海量文献数据为基础，用量化统计和可视化的方法，客观梳理一个研究领域的发展脉络、研究热点、合作网络和前沿趋势。

它和普通文献综述最大的区别是：普通综述偏主观归纳总结，而文献计量是数据驱动量化分析。统计文献的作者、机构、关键词、被引，做图谱；但图谱只是结果，必须结合人工读文献去解读背后的研究逻辑，不能只看图表。

具体实操逻辑分为两步：

第一是人工精读筛选。批量检索领域文献，剔除无效文献，人工梳理每篇文章的研究对象、研究方法、应用场景、核心关键词、作者和机构信息，建立标准化文献信息表，吃透领域真实研究内容，避免机器统计的片面性。

第二是数据可视化与专业解读。将清洗后的文献数据导入分析软件，生成关键词聚类、作者合作、机构合作、前沿演进等知识图谱。图谱只是可视化结果，真正的核心是结合我前期精读的文献内容，去解释图谱背后的学术逻辑，解读领域的研究热点、主流方向、合作规律和未来前沿，而不是单纯看图说话。
Q：这个信息表是怎么归纳的？
A：我做信息表主要归纳两件事：

一是客观的基本信息（标题、作者、年份、DOI）；

二是靠精读提炼的文章内容——因为课题是 XAI 在药物研发，我会重点记它的药物分类（化药 / 生物药 / 中成药）、研究方向（是药代动力学还是药物作用机制）、用了什么机器学习方法、模型 / 技术、以及最关键的有没有用可解释技术、用了哪一种（比如 SHAP、LIME）、是全局的还是局部的、它的优缺点以及用在了药物研发的哪个环节。
Q：你完整走完检索‑清洗‑筛选‑绘图全流程，遇到最大的难点是什么？
难点主要有两点：

难点 1：数据清洗——同名作者、机构名称不统一（比如同一个机构不同写法），需要人工统一；WOS 中作者名字可能有好几个。

难点 2：整理文献信息表的过程繁琐漫长——每篇文章都要精读、逐字段填表，是体力活也是细活。
